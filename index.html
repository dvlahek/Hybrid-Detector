Hybrid Gaussian–Wavelet Detector Lab

Interactive visualization of a multiscale detector landscape for zero localization. Choose a test function, adjust detector parameters, and compare reference zeros with detector-estimated zeros.

How to use this detector demo

1
Choose a test function.
Start with sin(x²) because it is the cleanest example. Then try damped, close-pair, chirp, synthetic zeta-zero, and custom functions to see how parameter choices affect zero localization.
2
Read the three plots.
Function View shows f(b). Main Detector Landscape shows log10 D(a,b) across position and scale. 1D Slice shows one horizontal scale slice of the detector. Good detection occurs when low detector valleys align with zeros of the function.
3
Compare colors.
Blue means a reference zero. Green means a detector estimate matched a reference zero. Orange means the detector produced an unmatched estimate. Red means a reference zero was missed.
4
Interpret the table.
The table reports matched, missed, and false-positive candidates. Pay special attention to support, persistence, and sign check. These are diagnostics that help explain whether a candidate is a stable multiscale valley.

Scope and paper alignment

  • This demo illustrates the detector framework from the paper.
  • The paper-default detector corresponds to α = 1, β = 1, and γ = 0.5.
  • Other α, β, and γ values are exploratory visualization parameters, not the default theorem setting.
  • The synthetic zeta-zero example is not the true Riemann Xi function.
  • The Riemann-like toy oscillation is qualitative only and should not be used for quantitative claims.

Detector formula

  • P(a,b) is the Gaussian-smoothed local amplitude.
  • W(a,b) is a wavelet-like local variation response, implemented here by a derivative-of-Gaussian proxy.
  • The plotted detector is log10 D(a,b), because detector values can vary strongly across scales.
  • In the paper setting, zeros are sought as local minima of D(a,b).
  • In the plots, stable valleys across scales indicate candidate zero regions.

Color meaning

  • Blue: reference / true zero.
  • Green: detector estimate that matches a reference zero.
  • Orange: unmatched detector estimate / false positive.
  • Red: reference zero missed by the detector.
  • White dotted horizontal line in the heatmap marks the scale used by the 1D slice.

Function and view controls

  • Test function: selects the function whose zeros are localized.
  • Domain min / max: controls the interval searched for zeros.
  • Main visualization: choose 2D heatmap for clear interpretation or 3D surface for geometric intuition.
  • Custom function: lets you enter your own function of x.
  • Optional reference zeros: used only for evaluation and coloring, not for detector computation.

α alpha

  • Controls the influence of the Gaussian amplitude term |P(a,b)|.
  • Larger α makes the detector prefer locations where the smoothed function amplitude is very small.
  • If α is too high, weak or damped zeros may be suppressed.
  • If α is too low, amplitude information becomes less selective.
  • Paper default: α = 1.

β beta

  • Controls the influence of the wavelet / variation term in the denominator.
  • Larger β gives more importance to local variation and slope-like behavior near candidate zeros.
  • If β is too high, derivative-like artifacts or noise may become too influential.
  • If β is too low, the detector becomes closer to an amplitude-only method.
  • Paper default: β = 1.

γ gamma

  • Controls scale normalization through the factor a^γ.
  • It balances detector values between small and large scales.
  • Too small γ may make different scales less comparable.
  • Too large γ may over-penalize larger scales.
  • Paper default: γ = 0.5, corresponding to the sqrt(a) normalization.

ε epsilon

  • Small regularization term in the denominator.
  • Prevents numerical instability when the wavelet response is close to zero.
  • Too small ε may create sharp spikes or unstable detector values.
  • Too large ε weakens the wavelet term and makes the detector more amplitude-driven.
  • Typical values: 1e-8 to 1e-10 for clean demonstrations.

Noise level

  • Adds deterministic pseudo-noise to the sampled function.
  • It is useful for testing robustness and visualization, but it is not a statistical noise model.
  • With more noise, use larger scales, stronger support filtering, or lower minima quantile.
  • For clean interpretation, start with 0.

Scale parameters

  • a_min: smallest scale. Smaller values sharpen valleys but require a finer grid and are more sensitive to noise.
  • a_max: largest scale. Larger values smooth noise but may merge nearby zeros.
  • Number of scales: how many scales between a_min and a_max are evaluated.
  • More scales improve persistence diagnostics but increase runtime.
  • For dense zeros, reduce a_max and often reduce a_min.

Grid points

  • Controls how many spatial samples are used in the search interval.
  • More grid points improve spatial resolution and reduce missed narrow valleys.
  • Too few grid points can miss zeros even if the detector formula is appropriate.
  • Rule of thumb: grid spacing should be clearly smaller than a_min.
  • The warning box alerts you when the grid is too coarse relative to scale.

Minima quantile

  • Controls how selective local-minimum extraction is at each scale.
  • Lower values keep only the deepest detector minima, usually improving precision.
  • Higher values keep more minima, usually improving recall.
  • If many true zeros are missed, increase this value.
  • If many orange false positives appear, decrease this value.

Merge tolerance

  • Clusters nearby minima across scales into one estimated zero.
  • If too large, nearby zeros can merge into one candidate.
  • If too small, one true zero can split into several candidates.
  • For close or dense zeros, use a smaller merge tolerance.
  • The warning box alerts you if merge tolerance is large relative to zero spacing.

Match tolerance

  • Used only for evaluation and coloring.
  • It decides whether an estimated zero is close enough to a reference zero to count as green/matched.
  • It does not change detector computation.
  • If it is too strict, good near-matches may appear as orange/red.
  • If it is too loose, evaluation can look artificially good.

Max estimated zeros

  • Limits how many detector candidates are reported after clustering and ranking.
  • If the domain has 40 true zeros but this value is 12, recall cannot exceed 12/40.
  • Increase it for long domains or dense-zero examples.
  • For simple demos, a smaller value keeps the plot readable.
  • The warning box alerts you if this cap is smaller than the number of reference zeros.

Minimum scale support

  • Filters candidates by how many scale-level minima contributed to the cluster.
  • Higher support means the candidate is more persistent across scales.
  • Increasing it usually reduces false positives.
  • Decreasing it usually improves recall but may allow weak candidates.
  • This is a diagnostic filter based on the multiscale candidate-merging idea.

Persistence score

  • Persistence is support / number of scales.
  • A persistence close to 1.00 means the valley appears across nearly all tested scales.
  • High persistence is strong evidence for a stable multiscale valley.
  • Low persistence suggests a weak, noisy, or scale-specific candidate.
  • Use persistence together with error and sign check, not as the only criterion.

Sign-check window

  • Checks whether f(b) changes sign near a detector candidate.
  • For ordinary simple zeros, a detector minimum plus sign change is a strong diagnostic.
  • This is not the main detector and is not part of the minimization principle.
  • No sign change does not automatically mean the candidate is wrong, because sampling, noise, or tangent zeros can affect it.
  • Use a window comparable to local spacing, but not so large that it covers several zeros.

Slice scale index

  • Selects which scale row is shown in the 1D slice plot.
  • Low index usually corresponds to small scale: sharper but noisier valleys.
  • High index usually corresponds to large scale: smoother but broader valleys.
  • Move this slider to see how minima sharpen, merge, or disappear across scales.
  • The heatmap marks the chosen slice with a white dotted horizontal line.

Auto-tune buttons

  • Auto-tune balanced: chooses moderate settings for a compromise between precision and recall.
  • Auto-tune dense zeros: increases grid/scales, lowers scale range, and increases the candidate cap.
  • These buttons are UI helpers, not part of the paper's formal algorithm.
  • Use them as a starting point, then fine-tune manually.

Download CSV

  • Exports the current detection table.
  • Includes status, reference zero, estimated zero, error, support, persistence, sign check, and detector value.
  • Useful for comparing parameter settings or preparing tables.
  • The CSV reflects the current visualization state only.

Precision vs recall

  • Precision: among detected candidates, how many are correct?
  • Recall: among all reference zeros, how many were found?
  • High precision and low recall means the detector is conservative.
  • Low precision means many false positives.
  • Low recall usually means too few candidates, coarse grid, scales too large, too much merging, or too strong support filtering.

When many zeros are missed

  • Increase Max estimated zeros.
  • Increase Grid points.
  • Increase Minima quantile.
  • Decrease Merge tolerance if neighboring zeros are merging.
  • Use smaller scales when zeros are dense.
  • Lower Minimum scale support if real valleys are visible but filtered out.

When false positives appear

  • Lower Minima quantile.
  • Increase Minimum scale support.
  • Check whether orange candidates have low persistence.
  • Use the sign-change column as a diagnostic.
  • Increase smoothing scale slightly if false positives come from noise.

Typical parameter recipes

  • Clean demo: Grid 400–600, a_min 0.04, a_max 0.30, quantile 0.35–0.55.
  • Dense zeros: Grid 800–1500, a_min 0.02–0.04, a_max 0.15–0.25, merge 0.05–0.12.
  • Noisy function: increase a_max, avoid very small a_min, and use stronger support filtering.
  • High recall: increase Max estimated zeros and Minima quantile.
  • High precision: lower Minima quantile and increase Minimum scale support.

Function-specific advice

  • sin(x²): good default; demonstrates sharpening valleys as scale decreases.
  • Close-pair polynomial: use small scale and small merge tolerance to avoid merging two zeros.
  • Damped functions: if distant zeros are missed, reduce α or increase minima quantile.
  • Synthetic zeta-zero test: controlled toy function with zeta-zero ordinates built in as exact zeros. It is not the true Riemann Xi function.
  • Riemann-like toy oscillation: qualitative only; do not judge precision/recall against true zeta zeros.
  • Custom function: provide reference zeros manually if automatic sign-change estimation misses non-crossing or very dense zeros.

Custom function syntax

  • Use x as the variable.
  • Allowed helpers include sin, cos, tan, exp, log, sqrt, abs, pow, PI, and E.
  • Examples: sin(x*x), exp(-0.05*x)*sin(6*x), (x-1.2)*(x-3)*(x-4.8).
  • Optional reference zeros are comma-separated numbers.
  • Reference zeros are used only for evaluation and coloring, not for detector localization.

Detector as preprocessing

  • The detector does not need to deliver final high-precision roots.
  • Its main role is basin localization and initialization.
  • Practical pipeline: detector candidate → local bracket → Brent refinement.
  • Alternative: detector candidate → Newton refinement.
  • This demo stops at localization; classical solver refinement is the natural next step.

Scientific interpretation: this demo visualizes zero localization as a multiscale minimization problem. It intentionally stays close to the detector framework: Gaussian amplitude, wavelet-like variation, scale normalization, local minima, multiscale persistence, and optional sign-change diagnostics.
